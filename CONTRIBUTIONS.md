These define the Goals, Principles, Scope and Philosophies of this project.
I list them here mainly as a reference for myself, I try my best to develop this software with these principles in mind or to update them if/when necessary as the project matures.
These are probably helpful to read through if you intend to contribute to this project.

# General Idea #
An application that allows the user to, with minimal effort, look up (English) definitions of Japanese words appearing anywhere on their computer screen. The user can, in convenient ways, pass a string of Japanese text to the application, with no artificial limit as to the length of the string, which is then displayed in the application in an easily readable format. The user can select Japanese words in the displayed string to have its (English) definition displayed. 
  
The application attempts to reduce the friction between the user seeing Japanese text on their screen and reading word definitions as much as possible. To fulfill the project's goals, the user must be able to look up Japanese text being displayed on their screen in any (feasible) scenario in an instant. Friction must also be reduced in the setup and usage process, meaning that a a perfect initial user experience would look like: Download app -> launch -> pass text -> see definitions.
 
# Guiding Principles: #
 - **Target platforms:** The main target platform of this app is Linux (both Wayland and X11). Windows is targeted as an after-thought but as a thought nonetheless. All other Operating Systems are third-class targets, receiving only basic attention.
 - **Offline-first:** The app must be fully usable while the user is offline. All features must be developed with offline functionality in mind. Internet requirements should either be infrequent/optional (e.g. one-time dependency downloads) or only exist to enhance features that otherwise still work offline (e.g. an extra online-only OCR method).
 - **Fast launch:** Optimization of launch speed of the app takes high priority. The application is a "popup" dictionary which shows the user a dictionary as instantaneously as possible. Feature additions or architecture changes that slow down the launch speed of the app must face high scrutiny. (This somewhat restricts the idea of implementing a background daemon to avoid long load times on subsequent uses, since the user may not have the daemon running in a given situation and therefore has to expect a long startup on first use).
 - **Low overhead:** Optimization of the resource footprint of the app takes high priority as well. This includes the size of the app itself, the size/amount of dependencies and the resource usage at runtime. A best effort must be made to keep a small-sized footprint even as new features are added. This tenet can sometimes be in opposition to the fast launch one. In such situations, a slightly bigger resource footprint can be acceptable, in moderation, to allow for a faster launch speed. This is a fine balancing act. Additionally, features using a higher amount of resources may be implemented, however they must be entirely optional and not using them should not present a seriously degraded user experience (e.g. Optional CUDA support for OCR is okay if other good non-CUDA options exist).
 - **Accessibility:** Whilst the app should be easy to set-up and use, it must also come with a high degree of configurability. The app should make minimal assumptions as to how the user wants the app to behave and how they want to use it/interact with it, providing a sane default but allowing as many aspects as possible to be explicitly configured as well as different ways to use it.
 - **Quality over quantity:** Quality is a core tenet during development of this app. Since this is mainly a passion project, no cheap shortcuts will be taken just to release features faster. The developer(s) will take their time to work on each feature for as long as they see fit and only add new ones when they believe a genuine need exists as well the capabilities to properly maintain them. There is an expectation for contributions to keep up a similar level of effort (and quality), low effort contributions (e.g. cheap LLM-generated code) will be ignored.
 - **Respecting peoples' works:** During all aspects of development and contribution, a genuine effort must be made to respect other peoples' works and to uphold their creative rights. License notices and attributions must be made for all usage of other peoples' creative properties. Considering its unknown licensing/copyright status, LLM-generated code can currently not be accepted.
